# 资产引用机制

> 三大资产如何被 Prompt Engine 引用的完整机制。  
> 关联文档：[../workflow/一致性系统设计.md](../workflow/一致性系统设计.md)

---

## 资产引用总览

```
项目（Project）
  │
  ├── Story（故事）
  ├── Visual Style（视觉风格） ──→ style_prompt
  ├── Characters[]（角色资产）──→ visual_prompt[]
  ├── Locations[]（场景资产） ──→ visual_prompt[]
  │
  └── Scripts → Episodes → Scenes → Shots
                                      │
                                      ├── character_ids[] ──→ 引用 Characters
                                      └── scene_id ──→ Scene.location_id ──→ 引用 Location
```

---

## 三大引用关系详解

### 1. characters 与 shots 关系

```
characters (1) ───── (N) shots
  ↑ 多对多，通过 shots.character_ids (jsonb 数组)
```

| 项 | 说明 |
|----|------|
| 存储方式 | `shots.character_ids` = `["char-uuid-1", "char-uuid-2"]` |
| 引用方向 | Shot → Character（通过 ID 查询） |
| 一对多 | 一个角色出现在多个镜头 |
| 多对多 | 一个镜头可涉及多个角色 |
| Prompt 引用 | 图片 Prompt 生成时，通过 character_ids 查询角色 visual_prompt，拼入 Prompt |

**为什么用 jsonb 而非关联表**：
- 多对多关系简单，无需额外关联表
- jsonb 数组查询方便（Supabase 支持 jsonb 查询）
- 镜头删除时不影响角色资产

### 2. locations 与 scenes 关系

```
locations (1) ───── (N) scenes
  ↑ 一对多，通过 scenes.location_id (外键)
```

| 项 | 说明 |
|----|------|
| 存储方式 | `scenes.location_id` = 外键引用 locations.id |
| 引用方向 | Scene → Location（外键） |
| 一对多 | 一个场景资产可被多个 Scene 引用 |
| 引用链 | `shot.scene_id → scene.location_id → location.visual_prompt` |
| Prompt 引用 | 图片 Prompt 生成时，通过 shot→scene→location 获取场景描述 |

### 3. visual_styles 与 projects/prompts 关系

```
visual_styles (1) ───── (1) projects
  ↑ 一对一，通过 projects.visual_style_id (外键)
```

| 项 | 说明 |
|----|------|
| 存储方式 | `projects.visual_style_id` = 外键引用 visual_styles.id |
| 引用方向 | Project → Visual Style |
| 一对一 | 一个项目绑定一个视觉风格 |
| Prompt 引用 | 图片 Prompt 生成时，通过 project.visual_style_id 获取 style_prompt |

> 注：visual_styles 不直接关联 prompts 表，而是在 Prompt Engine 运行时动态查询注入。

## Prompt Engine 引用流程

```
用户选择镜头 → 点击"生成图片 Prompt"
                    ↓
        Context Builder 启动
                    ↓
    Step 1: 查询 shot（获取 character_ids, scene_id）
                    ↓
    Step 2: 查询 scene（获取 location_id）
                    ↓
    Step 3: 查询 location → 获取 visual_prompt（场景固定描述）
                    ↓
    Step 4: 查询 characters WHERE id IN (character_ids)
            → 获取每个角色的 visual_prompt[]
                    ↓
    Step 5: 查询 project → 获取 visual_style_id
                    ↓
    Step 6: 查询 visual_style → 获取 style_prompt（风格固定描述）
                    ↓
    Step 7: 查询 story → 获取 synopsis/genre/worldview
                    ↓
    Step 8: 查询 prompt_template → 获取平台模板规则
                    ↓
    组装 System Prompt:
      [平台模板规则]
      + [角色 visual_prompt 拼接]
      + [场景 visual_prompt]
      + [风格 style_prompt]
      + [镜头上下文：动作/情绪/摄影语言]
                    ↓
    AI 生成 → 输出完整图片 Prompt
                    ↓
    保存到 prompts + prompt_versions
```

## 资产缺失处理

| 场景 | 处理 |
|------|------|
| 镜头无 character_ids | 跳过角色描述，仅生成场景+风格 Prompt |
| Scene 无 location_id | 返回 400，提示"请先为该场景绑定场景资产" |
| Project 无 visual_style_id | 使用默认风格 Prompt 或提示用户选择风格 |
| Story 不存在 | 使用 project.synopsis 作为替代上下文 |

## 资产编辑影响传播

| 资产编辑 | 已有 Prompt | 新生成 Prompt |
|----------|-------------|----------------|
| 编辑角色 visual_prompt | 不自动更新 | 应用新描述 |
| 编辑场景 visual_prompt | 不自动更新 | 应用新描述 |
| 切换项目 visual_style | 不自动更新 | 应用新风格 |

**设计决策**：不自动传播，需用户手动重新生成，避免覆盖用户已编辑的 Prompt。
