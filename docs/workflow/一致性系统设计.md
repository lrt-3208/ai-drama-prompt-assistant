# 一致性系统设计

> 多镜头一致性解决方案 — V2 架构核心。  
> 关联文档：[../assets/资产引用机制.md](../assets/资产引用机制.md)

---

## 问题定义

AI 短剧制作中最大的痛点：**多镜头内容不一致**。

| 问题 | 表现 | 原因 |
|------|------|------|
| 人物变化 | 同一角色在不同镜头中外貌不同 | 每次独立描述人物，细节漂移 |
| 场景变化 | 同一地点在不同镜头中布局不同 | 每次独立描述场景，元素不一致 |
| 风格变化 | 整体画面基调不统一 | 无全局风格约束 |

---

## 解决方案：创作资产中心

通过**三大资产**的固定描述 + **Prompt Engine 上下文引用**，实现跨镜头一致性。

```
创作资产中心
├── Character 资产 → 固定 visual_prompt（人物外貌锁定）
├── Location 资产  → 固定 visual_prompt（场景元素锁定）
└── Visual Style 资产 → 固定 style_prompt（画面风格锁定）
        ↓
Prompt Engine 生成时自动引用资产固定 Prompt
        ↓
所有镜头的 Prompt 都包含相同的角色/场景/风格描述
        ↓
用户复制到第三方平台 → 生成结果视觉一致
```

---

## 一致性保障机制

### 1. 角色一致性

**机制**：每个角色拥有 `visual_prompt` 固定描述字段。

```
角色：林晚
固定 visual_prompt：「25岁亚洲女性，黑色长直发，清冷五官，修长身材，电影写实风格」
```

**引用方式**：所有引用林晚的镜头，其图片 Prompt 自动包含上述固定描述。

**效果**：即梦/MJ/Flux 生成时，人物外貌特征锁定，跨镜头一致。

### 2. 场景一致性

**机制**：每个场景拥有 `visual_prompt` 固定描述字段。

```
场景：医院门口
固定 visual_prompt：「现代医院入口，深夜暴雨，霓虹灯倒影在水洼，冷青色调，电影氛围」
```

**引用方式**：同一场景的所有镜头共享该描述。

**效果**：不同镜头中的同一地点，环境元素一致。

### 3. 风格一致性

**机制**：每个项目绑定一个 `visual_style`，拥有 `style_prompt`。

```
风格：都市复仇短剧风格
固定 style_prompt：「都市复仇短剧风格，冷蓝灰色调，电影摄影，高对比光影，50mm镜头，16:9」
```

**引用方式**：项目内所有镜头的图片 Prompt 都附加该风格描述。

**效果**：全片画面基调统一。

## Prompt 引用流程

```
用户选择镜头 → 生成图片 Prompt
       ↓
Prompt Engine 启动
       ↓
Context Builder 汇聚上下文：
  1. 查询 shot.character_ids → 获取角色 visual_prompt[]
  2. 查询 scene.location_id  → 获取场景 visual_prompt
  3. 查询 project.visual_style_id → 获取风格 style_prompt
  4. 查询 shot 本身信息（动作/情绪/摄影）
       ↓
组装 System Prompt：
  平台规则 + 资产固定 Prompt + 镜头上下文
       ↓
AI 生成 → 输出完整 Prompt
       ↓
保存到 prompts + prompt_versions
```

## 一致性 vs 灵活性

| 场景 | 一致性 | 灵活性 |
|------|--------|--------|
| 角色外貌 | 固定（锁定 visual_prompt） | 服装/表情可变（镜头级描述） |
| 场景环境 | 固定（锁定地点元素） | 时间/天气可变（镜头级覆盖） |
| 画面风格 | 固定（项目级锁定） | 不可变 |
| 镜头摄影 | 不固定 | 每镜头独立描述 |

**原则**：资产级固定 + 镜头级灵活。

---

## 资产编辑与影响传播

当用户编辑角色/场景/风格资产后：

| 操作 | 影响 |
|------|------|
| 编辑角色 visual_prompt | 该角色所有已有 Prompt 不自动更新；重新生成时应用新描述 |
| 编辑场景 visual_prompt | 同上 |
| 切换项目 visual_style | 同上 |

**设计决策**：资产修改不自动重生成已有 Prompt（避免意外覆盖用户编辑），需用户手动触发重新生成。

## 参考图片机制（扩展预留）

| 资产 | 字段 | 用途 |
|------|------|------|
| Character | reference_image_url | 角色参考图，未来图生图时作为 reference |
| Location | reference_image_url | 场景参考图 |
| Visual Style | visual_references | 风格参考影视作品名 |

> MVP 阶段 `reference_image_url` 可为空，仅用文本描述保证一致性。  
> V2 接入图片生成 API 后，参考图可用于图生图，进一步提升一致性。
